# FRAME / DNA · 参考图反推工作台

当前版本：`v0.9.0`

一个本地优先的图片与视频提示词工作台。它把参考图、产品图、构图调整、视觉语义分析和双平台提示词整理放在同一个界面中，帮助创作者把“我想要这种画面”变成可以在 Midjourney、GPT Image 2 等平台复用和继续修改的提示词。

> 这是本地工作台，不是在线生图服务。图片分析和提示词生成通过本机已登录的 Codex CLI 完成；软件本身不会直接调用 Midjourney 或 GPT Image 2 出图。

## 1. 项目解决什么问题

使用不同生图或视频平台时，常见问题是：

- 参考图中的主体、构图、光线和风格难以准确描述；
- 同一画面在 Midjourney、GPT Image 2 等平台之间难以保持一致；
- 提示词越来越长，修改一个构图要求时容易破坏其他要求；
- 参考图、生成结果、英文提示词、中文对照和美学分析分散在不同软件或聊天记录中；
- 竖图扩展为横图时，主体位置和安全区域难以控制；
- 视频只想分析其中一段或几帧，却不得不处理整条视频。

本项目提供一个本地工作流：导入参考素材 → 选择分析范围 → 反推画面结构 → 编辑语义层和构图 → 生成双平台提示词 → 保存为项目或视觉资产。

## 2. 主要功能

### 图片反推

- 上传一张主参考图，可选上传产品／主体参考图；
- 支持局部框选、目标画幅和空间锚点调整；
- 可选择风格、空间、构图、镜头、光线、色彩、材质、氛围等分析范围；
- 导演要求可以留空，留空时只反推参考画面，不额外编造故事；
- 提供“快速结果”和“分层分析”两种模式；
- 分层模式会区分画面事实与 AI 推断，并支持启用、锁定、编辑和重新编译；
- 支持忠实还原、平衡扩写、创意增强三套候选方向，并可将采用的方案写回提示词框。

### 双平台提示词

- Midjourney 提示词：英文执行版、中文理解版、参考图用法、参数和排除项；
- GPT Image 2 提示词：中文执行版、英文对照、图片角色、编辑边界和排除项；
- 可单独复制 Midjourney 完整命令或 GPT Image 2 提示词；
- 支持中英文切换和手动编辑；
- Midjourney 参数会限制为可识别的 `--ar`、`--s`、`--c`、`--no` 等格式。

### 产品提示词工坊

- 输入产品图、场景参考图或一段产品想法；
- 支持“产品反推”和“场景续写”；
- 场景参考图可以指定为风格参考、构图参考或两者同时参考；
- 输出产品身份锁定、场景方向及 Midjourney／GPT Image 2 双平台提示词。

### 平台封面与构图

- 小红书 `3:4`、视频号横版 `16:9`、视频号竖版 `9:16` 预设；
- 预览主体焦点、安全区和裁切位置；
- 导出封面 PNG，并复制对应的平台封面提示词补丁；
- 支持参考图从竖构图扩展到横构图时调整主体位置。

### 视频拉片

- 支持导入 `MP4`、`MOV`、`WEBM`；
- 先设置入点和出点，只分析指定片段；
- 自动取帧或手动采集关键帧，最多分析 8 张已选帧；
- 关键帧可以取消、删除，或设为图片反推的主参考图；
- 输出画面事实、镜头语言、连续性锁定、静态图像提示词和动态视频提示词；
- 支持导出 LibTV 15 字段 Markdown 分镜表。

### 视觉资产库

- 保存主参考图或生成结果图对应的双平台提示词；
- 保存英文提示词效果图、中文对照和提示词美学分析；
- 自动生成“效果图＋提示词”的分享卡 PNG；
- 卡片可复制提示词、查看原图、下载分享卡、更新分享卡或删除资产；
- 数据保存在本机，不上传到云端。

### 项目与桌面体验

- 本地项目库：保存参考图、生成结果、语义层、锚点、提示词和版本快照；
- 首页总览当前项目、主参考图、资产和视频状态；
- 暗色、亮色和彩色三套主题，首次打开默认彩色；
- 提供浏览器版和 Electron 原生桌面版；
- 启动、分析、失败和超时状态会在界面中显示具体反馈。

## 3. 安装方法

### 环境要求

- macOS（当前 Electron 打包目标为 Apple Silicon arm64）；
- Node.js 和 npm；
- 已安装并登录 ChatGPT 桌面版附带的 Codex CLI；
- 首次安装需要联网下载 npm 依赖。

### 安装依赖

```bash
git clone <你的 GitHub 仓库地址>
cd reference-prompt-workbench
npm install
```

如果使用本地源码目录，也可以直接进入项目目录执行 `npm install`。

## 4. 使用方法

### 浏览器版

启动本地服务：

```bash
npm start
```

然后打开：<http://127.0.0.1:4317>

不要直接双击 `public/index.html`，也不要使用 `file://` 地址打开，否则会绕过本地接口。

基本流程：

1. 进入“图片反推”，上传主参考图；
2. 根据需要上传产品／主体参考图；
3. 选择目标画幅、反推范围和快速／分层模式；
4. 可选填写导演要求、选择空间锚点并调整局部框选；
5. 点击“反推并扩写目标画面”；
6. 在 Midjourney 和 GPT Image 2 两个提示词区域中复制或编辑结果；
7. 如需长期复用，点击“存主参考图”或进入“视觉资产库”保存资产。

### Electron 桌面版

开发启动：

```bash
npm run desktop:dev
```

生成 macOS `.app` 和 `.zip`：

```bash
npm run package:desktop
```

发布文件会生成在 `release/`。当前发布包是本地测试版，正式售卖前还需要 Apple 签名、公证、隐私政策、更新机制和授权流程。

### 常用验证命令

```bash
npm run check
npm test
npm run test:desktop
```

## 5. 输入输出示例

### 示例 A：参考图反推

输入：

```text
主参考图：一张未来主义城市夜景图
目标画幅：16:9 横向电影画面
反推范围：主体、空间、构图、镜头、光线、色彩、材质
导演要求：保留主体位置，不新增人物，增强远景空间层次
模式：分层分析
```

输出内容：

```text
整体判断：冷蓝夜景、暖橙局部灯光、广角大场景、主体位于左下三分之一。

视觉语义层：
- 构图关系：前景主体作为比例尺，中景城市形成引导线，天空保留大面积留白。
- 光线设计：冷色环境光与局部暖色人工光形成对比。
- 材质细节：湿润金属、玻璃反射、低饱和雾气。

Midjourney · English：
cinematic wide shot of a futuristic city at night, ... --ar 16:9 --s 200 --no text, logo

GPT Image 2 · 中文：
高写实电影感的未来城市夜景，保留主体位于左下三分之一……
```

上面的英文和中文是输出结构示例；实际提示词会根据上传的参考图和选择的要求生成。

### 示例 B：保存视觉资产

输入：

```text
资产名称：冷蓝未来城市夜景
效果图：city-night.png
英文提示词：cinematic wide shot of a futuristic city at night, ...
```

输出：

```text
asset-library/<资产 ID>/
├── asset.json          # 名称、标签、双平台提示词和美学分析
├── image.png           # 原始效果图
└── share-card.png      # 画面与提示词分享卡
```

### 示例 C：视频片段分析

输入：

```text
视频：reference.mp4
分析片段：00:04.0 - 00:12.0
已选关键帧：6 张
要求：优先拆解机位、镜头运动、主体连续性和光线变化
```

输出：

```text
镜头 01：开始时间、结束时间、景别、机位、摄影机运动、焦距与景深
静态首帧提示词：用于重建该镜头起始画面
动态视频提示词：用于描述镜头运动和主体变化
LibTV 15 字段 Markdown：可复制到后续分镜工作流
```

## 数据与隐私边界

- 项目文字和提示词保存在浏览器 `localStorage`；
- 保存项目后，参考图、产品图和结果图写入本机项目目录；
- 视觉资产写入本机 `asset-library/`；
- 反推时，选中的图片会通过本机 Codex CLI 发送给当前 Codex 服务；
- 视频在浏览器本地解码，只有已选分析片段中的关键帧会发送给 Codex；
- 不要把个人图片、资产库、API Key 或 Codex 登录配置提交到 GitHub。

## 当前不包含

- 直接调用 Midjourney 或 GPT Image 2 出图；
- 在线多人协作和云同步；
- PSD／透明 PNG 自动分层；
- 直接写入 LibTV、即梦或其他第三方项目；
- 完整的在线 SaaS 账号、计费和权限系统。

## GitHub 发布边界

仓库只应提交源码、schema、测试和文档。本地项目、视觉资产、`node_modules/`、Electron 安装包和运行日志已由 `.gitignore` 排除。把代码上传到 GitHub 不等于已经部署成在线服务；如果要在线运行，需要单独设计后端、AI 服务、图片存储、用户认证和隐私政策。
